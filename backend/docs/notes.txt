1. db style changes : `Column()` is the older SQLAlchemy style where you only define the database column, while `Mapped[type] = mapped_column()` is the modern SQLAlchemy 2.0 style that defines both the database column and the Python type of the attribute. Both create columns in the database, but `Mapped` provides better type checking, IDE autocomplete, and cleaner integration with modern Python typing. For new projects, you should generally use `Mapped[...]` with `mapped_column()` consistently throughout your models.


2. The `organization` and `candidate` fields are SQLAlchemy relationship definitions that connect the `User` model to the `Organization` and `Candidate` models. They do not create database columns; instead, they allow you to access related records directly through Python objects. For example, if a user is an organization user, you can simply write `user.organization` to get that user's organization profile without manually writing a SQL query. The `back_populates="user"` part creates a two-way connection so that from an organization you can access its user using `organization.user`. The `uselist=False` parameter means the relationship is one-to-one, so a user can have at most one organization profile and one candidate profile. The `__repr__()` method is just a debugging helper that controls what gets displayed when you print a `User` object, making logs and debugging output more readable.
